# SuperAutoStudy — Windows 桌面版

超星学习通自动刷课工具。自带 **JDK 8 + MySQL 5.7 + 后端 + 桌面客户端**，目标机**不需要安装 Java / MySQL / Python**，装完即用。

> **本仓库是 [DuanInnovator/SuperAutoStudy](https://github.com/DuanInnovator/SuperAutoStudy) 的二次开发版本**，遵循 **Apache-2.0** 许可。
> 原项目面向服务器部署（Spring Boot + Dubbo + RabbitMQ + Redis）；本版本将其轻量化到**单机可跑**，并补上了开箱即用的 **Windows 桌面客户端**与安装包。
> 详细的署名与改动说明见 [参考出处与致谢](#参考出处与致谢) 与 [相对原项目的改动](#相对原项目的改动)。

> **本包不含任何账号信息。** 数据库是空的，首次使用请自己在「登录 / 选课」页登录。

## 特性

- **登录 / 选课** — 账号密码登录（会真实去超星验证一次），勾选课程加入队列
- **多池刷课** — 默认 3 个并发池，同时推进 3 门课
- **进度可视化** — 总览看板（课程总数 / 进行中 / 已完成 / 异常）+ 实时「正在刷的视频」卡片
- **每条视频进度** — 点任意课程的「任务点」，按章节列出每条视频的名称、时长、已播时长、进度条、是否通过
- **原生桌面窗口** — pywebview + Edge WebView2，没有地址栏
- **设置热生效** — 改完点「保存并重启后端」，参数立刻生效

1. 解压从 Releases 下载的 `SuperAutoStudy-portable.zip`，把里面的 `SuperAutoStudy` 文件夹拷到目标电脑的**任意位置**（路径可以有中文/空格，但别放 C 盘根目录）

> **换目录后必须重跑一次启动脚本** —— 它会按当前路径重写 `my.ini`，否则 MySQL 会因为路径不对起不来。

## 界面说明

顶部五个页签：

| 页签 | 内容 |
|---|---|
| **总览** | 课程总数 / 进行中 / 已完成 / 异常 四个数字；「正在刷的视频」实时卡片；最近完成的视频 |
| **课程队列** | 每门课的 courseId、优先级、状态、整体进度、当前在刷哪一条；每行三个操作：`任务点` / `优先级` / `移除` |
| **登录 / 选课** | 超星账号密码登录；勾选课程 `加入队列` |
| **设置** | 上报间隔、并发线程数、单视频最大遍数、全局跳过的任务点类型、只刷视频的课程 ID |
| **日志** | 后端日志实时跟随，支持关键字过滤、只显示告警、自动滚动 |

### 「任务点」弹层

在「课程队列」里点任意课程的 **`任务点`** 按钮，会弹出该课程**按章节分组**的完整任务点清单——每条视频的名称、时长、已播时长、进度条、是否已通过，一目了然。

- 第一次打开某门课要**扫描 1~2 分钟**（弹层里有实时进度条，显示「已扫描 N / M 章」）
- 扫完会缓存 5 分钟，期间再点秒开；也可以点右上角「重新扫描」强制刷新
- 扫描只走**只读接口**，不会改变任何刷课状态

## 关于速度与进度（重要）

**这是本工具最容易被误解的地方，请务必看完。**

界面上每条视频有两个时间：

- **播放位置** —— 超星**实际记录**的进度（真正算成绩的那个）
- **已进行** —— 从这条视频开始刷到现在的**墙钟时间**

你会看到「已进行 6:43」但「播放位置」只有 2:14 —— **差了 3 倍，这是正常的，不是故障。**

**原因**：

1. 上报视频进度有一条**全局节流**：任意两次上报必须间隔 **≥ 60 秒**。这是为了避开超星风控（9010 验证码）—— 实测调到 10 秒会触发**账号级**风控，之后所有上报都不计分，反而更慢。
2. 这个 60 秒配额是**所有并发池一起抢**的，不是每池一个。
3. 每次上报只让位置前进 **60 秒**。

所以 N 个并发池时，每条视频的位置只以 **1/N 的速度**前进：

| 并发数（`core_size`） | 效果 |
|---|---|
| `1` | 1 门课，**1 倍速** |
| `3`（默认） | 3 门课，**各 1/3 倍速**，总速度相同 |

**并发不会让总速度变快**，只是把同样的速度分给了更多课。想尽快刷完某一门，就把并发降到 1。

> ⚠️ 另外：**重启后端会让进行中的视频从头开始**（启动自愈会把「进行中」重置为「待处理」）。所以不要频繁重启，会白白浪费进度。

## 配置项

客户端 `client/settings.json`（也可以在「设置」页改）：

| 键 | 默认 | 说明 |
|---|---|---|
| `video_report_pace_ms` | `60000` | 上报间隔（毫秒）。**不要低于 60000**，否则触发风控 |
| `core_size` | `3` | 并发池数量。见上一节，**不影响总速度** |
| `video_max_rounds` | `2` | 单个视频最多刷几遍 |
| `skip_job_types` | `["workid"]` | 全局跳过的任务点类型（`workid` = 做题 / 章节测验） |
| `video_only_course_ids` | `[]` | 只刷视频的课程 ID 列表 |

改完点 **「保存并重启后端」** 立即生效。后端启动日志里有一行 `[StudyProperties] 生效配置: ...` 可以直接对照。

仓库里的 `client/settings.example.json` 是模板；首次运行会按默认值生成 `client/settings.json`（该文件已被 `.gitignore` 排除）。

## 常见问题

**Q：双击后客户端起不来 / 一闪而过？**
A：客户端出错会弹一个 Windows 提示框说明原因。若连提示框都没有，用命令行跑一次看报错：

```
python\python.exe client\desktop.py
```

**Q：客户端显示「找不到 MySQL」或服务点一直是灰的？**
A：说明 `my.ini` 里的路径不是当前路径。便携版重新双击一次 `启动.cmd` 即可。

**Q：提示「MySQL 已在运行」但其实是别的程序的 MySQL。**
A：先确认 3306 端口是不是被占：`netstat -ano | findstr :3306`，把占用进程停掉再启动。

**Q：登录后课程列表是空的？**
A：确认账号下确实有正在进行的课；也确认能访问 `chaoxing.com`。

**Q：后端起来了但课程不刷。**
A：看客户端「日志」页，重点搜 `风控` / `9010` / `退避`。若命中风控，停手等 30 分钟以上再试，并把上报节奏保持 60 秒。

**Q：「任务点」弹层一直转圈 / 报错？**
A：那是正在扫描（弹层里会显示进度），一门课首次要 1~2 分钟。若直接报错，多半是超星风控或 cookie 过期——先去「登录 / 选课」页重新登录一次。

**Q：想恢复某门已经移出队列的课。**
A：在「登录 / 选课」页勾上它再点「加入队列」即可（不用重新登录）。

## 目录结构

```
SuperAutoStudy/
├─ 启动.cmd                      ← 双击这个（首次/换目录必跑）
├─ launch.cmd                    ← 真正的启动脚本（快捷方式指向它）
├─ app.ico                       ← 程序图标
├─ my.ini                        ← MySQL 配置（由启动脚本自动生成）
├─ jdk8/                         ← 自带 Java 8 运行时
├─ python/                       ← 自带 Python 3.13（含 pymysql / pywebview）
├─ client/                       ← 桌面客户端
│   ├─ desktop.py                ← 原生窗口入口
│   ├─ server.py                 ← 本地服务（:3080，读写数据库 / 代理后端）
│   ├─ settings.json             ← 刷课参数（设置页写这里）
│   └─ web/                      ← 界面（HTML/CSS/JS，无框架）
├─ mysql57/                      ← 自带 MySQL 5.7
│   └─ data/                     ← 数据库文件（tihai 库）
└─ app/
    ├─ live.log                  ← 后端实时日志（客户端「日志」页读这个）
    └─ target/SuperAuto-1.0-SNAPSHOT.jar
```

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Spring Boot 2.7 + Netty（`:3030`），Dubbo 2.7（`:20880`） |
| 数据库 | MySQL 5.7（`:3306`，库 `tihai`） |
| 客户端服务 | Python 3.13 标准库 + pymysql（`:3080`，静态托管 + 反向代理） |
| 客户端界面 | 原生 HTML / CSS / JS 单页，无框架 |
| 桌面外壳 | pywebview + Edge WebView2 |
| 打包 | Inno Setup 6（安装包）/ zipfile（便携版） |

数据库三张表：

| 表 | 用途 |
|---|---|
| `th_wk_queue` | 课程队列（课程、状态、进度、优先级） |
| `th_wk_log` | 刷课日志（每条任务点的上报记录） |
| `th_wk_user` | 登录态（账号、cookie） |

状态枚举（`th_wk_queue.status`）：`0` 待处理 / `1` 进行中 / `2` 队列中 / `3` 考试中 / `4` 已完成 / `5` 异常 / `6` 暂停

## 从源码构建

### 后端（Java）

需要 JDK 8 与 Maven：

```bash
cd app
mvn clean package -DskipTests
# 产物：app/target/SuperAuto-1.0-SNAPSHOT.jar
```

启动（数据库需先就绪）：

```bash
java -jar app/target/SuperAuto-1.0-SNAPSHOT.jar --server.port=3030
```

### 客户端（Python）

只需 Python 3.10+ 与 `pymysql`、`pywebview`：

```bash
pip install pymysql pywebview
python client/desktop.py      # 原生窗口
# 或者只跑本地服务，用浏览器打开 http://127.0.0.1:3080
python client/server.py
```

## 相对原项目的改动

> 依据 Apache License 2.0 §4(b)「必须使修改过的文件带有显著的修改声明」。

| 范围 | 改动 |
|---|---|
| **架构简化** | 移除原项目对 RabbitMQ / Redis 等中间件的依赖，任务队列改由 MySQL 表（`th_wk_queue`）驱动，使整套系统可在**单机**运行 |
| **桌面客户端（新增）** | 新增 `client/` 目录：Python 本地服务（`:3080`，静态托管 + 反向代理）+ 原生 HTML/CSS/JS 单页界面 + pywebview 原生窗口，替代原先仅有 API 的使用方式 |
| **每条视频进度（新增）** | 新增只读接口 `GET /api/points`，按章节列出全部任务点（含已完成）及其时长 / 已播时长 / 是否通过；异步扫描 + 5 分钟缓存，**不改变任何刷课状态** |
| **会话隔离（修复）** | 新增 `CourseUtil#forkSession()`，让只读接口使用独立的 cookie 会话，避免与正在运行的刷课线程互相覆盖账号 |
| **进度显示（修复）** | 后端上报时打印精确「播放位置」，客户端据此显示真实进度，替代原先按墙钟折算导致的高估 |
| **刷课稳定性（修复）** | 视频计分判定、风控退避、上报节流等若干修复；并将误用 `log.error` 输出的正常启动信息改为 `log.info` |
| **开箱即用打包（新增）** | 自带 JDK 8 / MySQL 5.7 / Python 3.13 的便携包，以及 Inno Setup 安装程序（免管理员权限、中文向导、可卸载） |
