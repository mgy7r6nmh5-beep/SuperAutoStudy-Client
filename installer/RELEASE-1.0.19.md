# SuperAutoStudy v1.0.19

发布日期：2026-10-31

这一版的主线只有一件事：**章节测验真的能做了，而且真的能交上去。**

v1.0.8 当时把做题整块删了（`[skip]答题功能已移除`），之后一直是「视频刷得完、
测验全留着」的半残状态。这一版把它接了回来，但不是全自动 —— 是
「抓题 → AI 出答案 → 你确认 → 提交」。

---

## 新增：章节测验

### 流程

刷课遇到 `workid` 任务点，不再跳过，而是：

1. 抓题（`api/work` + `ktoken`，跟完 302 到做题页）
2. 字体反爬解码（`cxSecretStyle` 字形轮廓 MD5 → `font_map_table.json`）
3. 整卷丢给 AI，一次要回 JSON
4. 落库，状态标成「待确认」，**然后继续刷下一章**
5. 你在「待确认」页逐题过一遍、改掉不对的，点提交

第 4 步的「继续刷」是硬要求：刷课线程核心线程数是 1，单课串行。在这里停下来
等用户点确认，整门课就卡死了。所以做题是异步的，不阻塞刷课。

### 界面

- 新增第 6 个标签页「待确认」，有未处理卷子时标题上带小红点
- 题目按题型渲染：单选 / 多选（可多选）/ 判断（对·错）/ 填空（输入框）/ 简答
- 每道题显示 AI 的置信度和理由，方便你判断要不要改
- **AI 没把握的题不预选答案**。那个答案正是被校验否掉的，预选上等于把人往坑里带，
  必须留空让你自己选
- 提交前会拦：有任何一题没答案就整份不交（交上去是确定扣分）

### AI 配置

「设置 → AI 作答」。接口填任何 OpenAI 兼容地址都行（`/v1/chat/completions`）。

实测数据（一份真实的 4 题章节测验）：

| 模型 | 正确 | 耗时 |
|---|---|---|
| `Qwen/Qwen2.5-7B-Instruct` | 4/4 | 3.8s |
| `THUDM/GLM-4-9B-0414` | 2/4 | 7.1s |

7B 那档够用，不必上大模型。**安装包不含 key**，第一次用要自己填。

## 修复

这三个都是「不真交一次根本发现不了」的坑，任何一个都会让做题功能整个白给。

### 1. `answerwqbid` 没拼，服务端只回一句「无效的参数：code-1！」

页面上这个 `<input>` 是空的，值由页面 JS 在点提交时拼出来：
`id1,id2,id3,` —— **末尾还多一个逗号**。我们不走 JS，只能自己拼。

原来它被 `name.startsWith("answer")` 那个过滤规则顺手扔掉了。少这一个字段，
服务端回的是 HTTP 200 + `{"msg":"无效的参数：code-1！"}`，从响应完全看不出
问题出在哪。

### 2. 表单 action 是裸相对路径，被拼到硬编码前缀上 → 404

`<form action="addStudentWorkNewWeb?_classId=...">`，页面里也没有 `<base>`。
浏览器是按**当前页面地址**解析的，而抓题时 `api/work?needRedirect=true`
会 302 到 `/mooc-ans/work/doHomeWorkNew`，所以相对路径落在 `/mooc-ans/work/` 下。

原来硬编码 `/mooc-ans/`，必然 404。现在把跟完 302 的最终地址记进
`QuizPaper.pageUrl`，提交时用 `URI.resolve()` 解析。

### 3. 已经交过的章节被当成新题，还会往「题目纠错」接口发

交过之后同一个 workId 再请求，超星不给做题页，直接跳到
`selectWorkQuestionYiPiYue`（我的答案 / 正确答案 那页）。这页里**也有**
`div.singleQuesId`，硬解能解出题目，但：

- 题型全是 `unknown`（批阅页没有 `TiMu[data]` 那个题型码）
- 页面上第一个 `<form>` 是「题目纠错」的，action 指向
  `fanyapbl.fy.chaoxing.com/questionError/addQuestion`

结果就是每重跑一次课程，「待确认」里多一份已经交过的卷子；点提交等于给每道题
报一次错，而且响应还是 200。

现在三层拦：抓题时认 URL 直接返回 `alreadySubmitted`；`submitQuiz` 再兜一层
（已交过的、host 不在 `chaoxing.com` 上、路径含 `questionError` 一律拒）；
`prepare` 按 `job_id` 去重，同一个任务点只留一条记录。

### 4. 小模型回复被截断，整批题目一起作废

原来不给 `max_tokens`，服务商默认值（有的只有 512）把 JSON 从中间截断，
`Unexpected close marker '}'`，一批题全废。

现在按题量算：`max(600, min(4096, 200 + 题数 * 150))`，并且
`finish_reason=length` 直接报「模型回复被截断」，不再当成解析失败。

### 5. 提示词改成硬约束

小模型（7B 这档）对「请返回 JSON」这种软话基本不理会。现在系统提示词是
硬约束 + 正反例：第一个字符必须是 `{`、禁止用 ``` 包裹、多选题只写一个字母
一定是错的、填空题不许重复题干里已有的字。

最后一条是实测出来的：题目「贯穿( )培养全过程」，AI 原来填
`人才培养全过程`，拼进题干变成「贯穿人才培养全过程培养全过程」。

- 便携包和安装包**都不含** `app/ai-config.json`（里面是你的 key）和
