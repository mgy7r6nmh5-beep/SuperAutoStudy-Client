# SuperAutoStudy v1.0.22

发布日期：2026-11-21

这一版只修一个 bug：**「续刷 / 重试」按钮对「系统异常」和「未刷完」的课程完全无效**，
点了永远返回「没有需要续刷的任务」——任务卡死在那里，只能眼看着进度不动。

---

## 修复：异常任务无法重新入队

### 现象

课程队列里几门课挂在「异常」或「未刷完」，状态是 `系统异常` / `未刷完：超星仍有 N 个待完成任务点`，
重试次数都到了 5。点界面上的「续刷 / 重试」，始终返回「没有需要续刷的任务」，
后端日志也不动（10:28 重启之后再没有任何播放记录），但三个服务进程都活着、接口秒回。

### 根因

客户端和服务端对「失败任务」的状态理解不一致：

- 后端（Java）把「系统异常 / 未刷完」写成 **queue.status = 0 + log.status = 5**；
- 客户端 `server.py` 的 `reset_stuck_tasks()` 却只捞 `queue.status IN (2, 5)`。

于是这批任务既不会被后端的 `StuckTaskRecover` 认为需要恢复（它打印「没有需要恢复的任务」），
也不会被客户端的「续刷 / 重试」捞回来——两边都认为对方会处理，结果谁都没处理。

### 改动

`client/server.py`：

1. 查询条件从 `q.status IN (2, 5)` 改为
   `q.status IN (2, 5) OR (q.status = 0 AND l.lstatus = 5)`；
2. 分类循环里相应把 `qstatus == 0 且 lstatus == 5` 识别为失败任务，
   走 `clear_retry=True` 清零重试额度并重新入队。

只改客户端，不动后端 jar 和数据库结构。

### 验证

- 改完 `py_compile` 通过，重启客户端后调 `/api/queue/reset`
  → 返回「重试 5 个失败任务 / 已重新入队」。
- 后端随即输出「续刷课程: 思想道德与法治 从第 17/77 章接着刷」，
  完成数 10 → 12，队列 `running` 从 0 变成 1，视频正常播放。
- 答题模式 `off` 不受影响：重跑后 14 条 `[skip]答题功能已关闭，跳过[workid]`，
  答题页保持空。

## 升级方式

本版只改客户端 `server.py` 一个文件，体积很小：

| 文件 | 说明 |
|---|---|
| `SuperAutoStudy-client-1.0.22.zip` | 客户端补丁，解压覆盖安装目录下的 `client/server.py` 即可 |

后端 jar、MySQL 数据、答题配置都不用动。
